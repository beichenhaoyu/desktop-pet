# ADR-0009：派单工作区 `.dispatch/` 不入库，被引用的取证输入收进库

- **状态**：已接受（2026-10-15 历史重写执行；优化清单 R4 本轮把口径写死并接上门禁）
- **相关**：[ADR-0005](0005-command-layering-thin-command-bodies.md)（它的取证输入就是这条要处置的那类东西）、
  [docs/process/CONVENTIONS.md](../process/CONVENTIONS.md)「派单工作区 `.dispatch/` 不入库」一条、
  [docs/process/HOST-BACKLOG.md](../process/HOST-BACKLOG.md) §3 验收证据矩阵的 `check:docs` 行

## 背景

PM 流水线（`pm-dispatch`）在项目根开一个工作区：`.dispatch/<功能名>/{ledger.md,cards/,prompts/,results/,work/}`（工作区，不入库）。
里面装的是过程件——任务卡、执行会话的回传原文、变异脚本、原始扫描表。三个事实决定了它必须有个明确的去向：

1. **它天然带机器痕迹**。早期副本里出现过以盘符开头的机器绝对路径和中文目录名（`A股盯盘质量加固`，工作区、不入库），
   S6（2026-10-11）先把带绝对路径的重复测试副本删掉、`work/` 进 `.gitignore`，但那只是止血。
2. **它是进度事实源，不是交付物**。`ledger.md` 记每张卡的状态、验收列写「怎么验的」、还有「PM 未复跑/待办」一节。
   这些东西每次派卡都在变，进库就等于把每次调度都变成一次文档提交。
3. **2026-10-15 做了一次历史重写**，把 `.dispatch/`（工作区，不入库）与 `.vscode/` 整目录从历史里摘掉——代价是**全部 commit sha 变了**，
   备份只能放在仓库外的 `D:/test/git-purge-backup-20261015`。这种操作没有第二次：既然已经付出这个代价，
   去向就必须写成约定，否则下一波又会把过程稿往库里塞。

清单 R4 给的三个候选去处里，两个被否：

- **迁 GitHub Issues/Projects**：卡片承载不了调度器的输入。任务卡头部四个字段（卡型 / Blocked by / 独占资源 /
  验收等级）和 §4 白名单是 `dispatch.cjs` 与 `check-cards.cjs` 的解析对象，白名单重叠还要当场判串行；
  Issues 的正文是自由文本，搬过去等于把「门禁 0 error 才许派」这条机器判据换成人工约定。
- **在 `docs/process` 下另开一个 dispatch 目录把过程稿入库**：等于把刚花掉一次历史重写的东西再放回来，而且过程稿的写入频率比代码还高，
  每次执行会话回传都产生一次文档 churn；外部贡献者读到的是一堆带内部代号的半成品。

## 决策

1. **`.dispatch/` 整目录不入库**，`.gitignore` 覆盖它；本地 `ledger.md` 仍是跨会话的唯一进度事实源。
   换机器要先取仓库外的备份，这一点写进约定而不是假装仓库里有。
2. **新波次的功能名一律 ASCII**（`arch-p2` 这种）。已有的中文目录属历史波次，**保留原名不改**——
   改名会让备份、旧引用、以及 `docs/` 里已经写下的历史坐标三头对不上。
3. **被入库文档当依据引用的取证输入，必须收进库**。判据不是"重要不重要"，而是"有没有库内文档拿它当依据"：
   ADR-0008 写「本 ADR 的每一条都对得上 T16 的编号」，而 T16 那份在工作区里——读者与外部助手打不开，
   这句话就等于没写。处置：`docs/process/T16-WIDGET-REALM-GAPS.md`（原件按回传时样子收录，不改写，
   里面的「PM 决策」项后来由 ADR-0008 定案，把后见之明写回快照会毁掉取证价值）。
   台账、卡片、原始扫描（如 `realm-deps.tsv`）这类过程稿仍留在工作区。
4. **确实要留历史坐标的，同一行必须写明「不入库」**；**文档里的路径坐标一律按仓库根相对写**，
   不出现盘符开头的绝对路径——CI 全新 checkout 和第三方机器上都打不开它。
5. **3–4 两条由机器拦，不靠约定自觉**：`tools/check-docs.mjs` 新增 **R-H**（八条门禁里的一条，CI 已跑）——
   反引号里以盘符开头的 token 直接判红；首段是 `.dispatch` 的 token 若同行没有「不入库」判红。
   为什么非得加一条规则：R-D 的判定是「首段必须命中七个入库顶层目录」，`.dispatch` 这种工作区目录（不入库）按设计就在它视野外，
   所以「文档把唯一证据点写到库外」这件事此前**任何门禁都看不见**——本机全绿、CI 全绿、读者打不开。
6. **例外走显式常量表**（`EXEMPT_TOKENS`，带出处）。当前唯一一条就是那条仓库外备份目录：
   它的绝对路径本身就是内容（"备份不在这个库里"），不是文档坐标。

## 后果

- 文档里引用工作区路径的成本从"没人发现"变成"当场红"。**这条规则在写出来的同一轮就抓到了自己的作者**：
  新写的 CONVENTIONS 约定条目漏标一处「不入库」当场红 1 条；这份 ADR 自己交上去时红 6 条
  （5 条 H2 漏标 + 1 条把「候选去向」当成路径引用），全部改在正文里而不是往白名单加词。
- 既有读数的方向只增不减（终值见 `docs/process/HOST-BACKLOG.md` §3 的 `check:docs` 行）：`rules=7` → `rules=8`，
  R-D 受检 token 239 → **253**（PLUGIN-BACKLOG 那批白名单路径改成仓库根相对之后**才第一次进入 R-D 视野**，
  且全部真实存在），R-A 链接 61 → **65**、R-E 配对 30 → **33**、R-G 树 98 → **99**、R-H `checked=19 exempted=2`。删项 0。
- CI 全新 checkout（没有 `.dispatch/`，那本来就不入库）里跑 R-H 是绿的，取证口径与本机一致；换机器的代价被写成"取备份"，
  而不是"库里应该有"。
- 这条不解决"外部助手看不到卡片原文"——那是设计：他们读的接口是 `docs/` 下三份文档（HANDBOOK / SDK / REVIEW），
  卡片里的白名单与验收等级是调度器的输入，不是给接活者看的规范。
