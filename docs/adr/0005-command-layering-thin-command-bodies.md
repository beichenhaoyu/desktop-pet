# 命令分层：命令留在能力域里，命令体收成薄层（清单 A1）

清单第 39 项给的是一道二选一：「commands 薄层」还是「服务自带命令」，验收写「约定写入 ADR；全部命令符合」。
**决定：命令继续与它的能力同模块（不搬目录），但命令体必须是薄层——业务规则一律下沉到可离线单测的函数，
并用一台机器守门（`tools/check-command-shape.mjs`，`npm run check:shape`）。**

守门的判据只有两条**不需要人工标注、可机械复现**的：
**S1 命令体里不许出现 IO 原语**（`std::fs`/`fs::`/`File::`/`read_to_string`/`read_dir`/`remove_file`/`rename`/`reqwest`/`send()`），
**S2 命令体非空行数 ≤ 20**。首跑读数：**7 条命令 8 处违例**（`permission_request` 82 行、`ble_start_scan` 68、`ble_connect` 45、
`overlay_show` 31、`pet_skin_remove` 25 且含 IO、`bus_publish` 24、`plugin_file_version` 含 IO），全仓中位数 9 行。

「规则必须住在可测函数里」这一维**不进 CI**：它依赖 T08 那套带人工标注的厚薄判据（`fat=17`），
把标注表写进 CI 就是把它冻住——标注会随代码漂移而腐烂。它的把关方式是**每次迁移验收时现场重跑
`.dispatch/arch-p2/work/T08/inventory.mjs` 报 fat 计数**（派单工作区里的过程稿，不入库；入库的那半是
`tools/check-command-shape.mjs`，它只跑 S1/S2/S3 这三条机械判据，`npm run check:shape`），
并由评审点名新抽出的函数各自的测试标题。

**为什么算决策**：两个候选其实问的是目录，而 T08 的取证说明真问题不在目录。把它写下来，
免得下一波人再从「把所有命令搬进 `commands/`」重新发明一次搬家。

## 取证（2026-10-13，卡 T08 全量清点，PM 独立复现）

- 48 条注册命令（`src-tauri/src/lib.rs:96` 的 `generate_handler![` 到 `])`）分布在三种宿主域：
  `window` 9、`commands` 7、`services` 32 —— **41/48 本来就与能力同模块**，`commands/` 反而是少数派。
- 厚薄：**17 厚 / 31 薄**。厚命令的标记分布是 `就地规则` 12、`事件` 8、`IO` 2、`多模块编排` 2（一条可多标）。
- 命令级测试覆盖**实际为 0**：T08 报的「有同名单测 = 11」全部来自 `gate_coverage.rs` 里的表内字符串，
  没有一条命令在测试里以调用形态出现。所以「已有测试兜着」这句话在本项上不成立，写 ADR 时按零覆盖起算。

## 约定（四条判据；其中 IO 与体行数进了机器门禁）

一条 `#[tauri::command]` 只有**薄**与**厚**两种合法形态，判据是命令体里出现什么：

| 违例（厚） | 处置 |
|---|---|
| 直接 IO（`fs::`、`read_to_string`、网络） | 挪进能力域的函数，命令体只委托 |
| 就地算出业务规则（构造/匹配数据后自己决定结果） | 抽成纯函数：入参是已有状态，出参是决策结构 |
| 跨模块编排（调 ≥2 个别的模块且中间有分支） | 编排函数放在其中一侧模块内，命令体只调一次 |
| 发事件（`emit` / `emit_to` / `eval`） | 把「要不要发、发哪个 topic、载荷是什么」抽成决策函数，`emit` 本身留在命令体 |

命令体允许做的只有四件事：参数与 id 校验 → 门禁判定 → **一次**委托 → 映射返回值。
`emit` 留在命令体是刻意的：它需要 `AppHandle`，把它塞进纯函数就等于把不可测的部分挪了个名字而不是消掉。
这个形状不是新发明的——H2 交付时已经这么做过一次（`decideHotReload` / `plugin_ids_from_paths` 两个纯函数，
Rust 侧离线钉住，运行时只验"事件真的按决策发出去了"）。

## 为什么不搬目录

1. **搬家不改变可测性**。17 条厚命令搬到 `commands/` 之后函数体一个字都不会变，仍然需要 `AppHandle`/`State`/`Window` 才能跑。
2. **搬家要付的账却是真的**：41 次 `use` 与可见性调整、§4 目录树整片重写、`gate_coverage.rs` 的反查逻辑跟着改、
   `check-docs` 的 R-B（只认 `services/` 那一层）当场失效——那一层判据还是 R8 刚纳管进 CI 的。
3. **跨切面已经有守门机制**。新增命令必须过门禁这件事由 `gate_coverage.rs` 从注册表反查保证，
   靠的是注册表而不是目录；再加一条「必须住在某个目录」的约定不会多拦下任何真实缺陷。

## 被否掉的三条路

- **全量搬进 `commands/`**：如上，代价付在形式上，收益为零。
- **只做目录约定、不动命令体**：等于宣布清单第 39 项完成，而实际不可测的东西一件没少。
- **顺手引入错误枚举/`thiserror`**：那是清单第 40 项（A2）的事，混进来会让本项的 diff 面从 17 个函数膨胀到整个 crate 的错误分支。A2 依赖本项先落地（先有薄命令体，`Result` 的替换面才收得住）。

## 后果与代价

- 以后新增命令必须过 S1/S2；`npm run check:shape` 会红，这条进 CI（与 `check:docs` 同级），所以约定不是文档承诺。
- S2 那道 20 行的线是**刻意粗**的：它不判断"这段是不是业务规则"，只保证命令体长到一定程度就必须拆开让人读过。
  真正的判断留在评审里，别把 CI 当成设计器。
- 解析算法与 `gate_coverage.rs:64`/`:79` 同源但**不共享代码**（那两个函数在 `#[cfg(test)]` 里，Node 侧调不到）。
  两份解析器会漂——已知点：三个文件的 `mod tests` 里有孤立大括号字面量（`gate_coverage.rs:98`、
  `services/agent_hooks.rs:350`、`services/enabled.rs:162`），朴素配对会退到文件尾；本工具只取命令体，不受影响。
- 迁移按违例逐条走，一条一测试：`plugins` 1、`skins` 1、`bus` 1、`window/overlay` 1、`ble` 2、`permission` 1。
  每片的验收都是同三件事：`cargo test --lib` 只增不减、`npm run check:shape` 的 `failing` 按片下降、
  被抽出的函数各自有**点得名的新测试标题**（不许用"重构不改行为"糊过去）。
